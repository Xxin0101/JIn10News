# BZ=F 极端波动展示与完整度设计

日期：2026-07-24
状态：已批准
适用范围：`run_jin10_tracker.py` 与 `jin10_market_report/` 下的 Brent 08:00 滚动日报链路。

## 1. 目标

修正当前把大幅价格跳变自动视为行情错误并隔离相关异动的行为。系统继续完整抓取、保存和展示 Yahoo Finance `BZ=F` 数据，保持“先识别价格异动，再反查新闻，最后由人工判断”的顺序。程序可以提示极端波动，但不得替人工断言价格一定错误，也不得因此隐藏已经抓到的价格、新闻或异动窗口。

本次同时加强读者可见的数据完整度说明，并确保 ISW Iran Update 和“今日关注什么”在正式版与 `PARTIAL` 版中始终存在。

## 2. 唯一标的

项目唯一价格标的是：

- `instrument_name`: `Brent Crude Oil Last Day Financ`
- `source`: `Yahoo Finance`
- `ticker`: `BZ=F`
- `contract_month`: 空
- `contract_type`: `Yahoo Finance BZ=F`

系统不讨论、不推断也不校验 `2609`、`2026年9月合约`、`BRNU26` 或 `BZU6`，不增加具体合约月份确认流程，也不更换价格标的。

上述标的信息写入日报的读者可见元数据和 Audit。`contract_month` 保持空值，不显示推断月份。

## 3. 已确认的数据事实

2026-07-24 对 Yahoo Finance Chart API 的只读核验表明：

- 返回标的为 `BZ=F`，`shortName` 为 `Brent Crude Oil Last Day Financ`，粒度为 `5m`。
- 本次响应的 306 个时间戳全部唯一且按时间升序，不存在原始时间戳重复或乱序。
- 其中 46 个时间戳的 OHLC 至少一项为空；现有解析器会跳过这些空 OHLC 行，得到 260 条有效 K 线。
- 86.06 直接来自 Yahoo 响应中北京时间 2026-07-23 16:20 的一根 K 线，该行 OHLC 均为 86.06。
- 23:35 至 23:45 的 87.17 至 100.34、约 +15.11% 跳变直接存在于 Yahoo 响应。
- 同一响应还直接包含其余三处绝对值超过 5% 的相邻有效 K 线跳变。
- SQLite 以 `(symbol, interval, ts_utc)` 为主键，数据库不会保存同一标的、周期和时间戳的重复行；当前异常不是重复行产生。

这些事实只能证明极端值来自 Yahoo `BZ=F` 源响应，不能证明它们一定正确或错误。因此系统应保留原始值和来源证据，把最终判断交给人工。

## 4. 价格处理设计

### 4.1 极端波动只作为提示

现有相邻 K 线绝对跳变阈值继续用于发现值得人工复核的时段，但改为纯诊断信号：

- 不改变 `price_freshness`；
- 不改变 `data_integrity`；
- 不改变 `FORMAL/PARTIAL/FAILED` 状态；
- 不生成 `INVALID`；
- 不删除或隔离价格异动窗口；
- 不清空新闻匹配、核心候选或首页新闻；
- 不从图表、最高价、最低价或涨跌幅中排除对应 K 线。

报告提示统一为：

> 本时段出现极端价格波动，可能与重大突发事件有关，需结合相关新闻人工判断。

Audit 继续列出跳变开始/结束时间、价格、幅度和间隔，作为人工核查线索，不使用“确定错误”“无效行情”等定性表达。

### 4.2 原始有效 OHLC 的参与范围

所有从 Yahoo `BZ=F` 返回且 OHLC 四项均为数值的 K 线，无论涨跌幅大小，都参与：

- 最新价；
- 当日最高价和最低价；
- 窗口涨跌幅；
- 30 分钟 K 线聚合；
- 异动窗口扫描与合并；
- 新闻时间匹配；
- 5/15/30/60 分钟反应计算；
- Markdown、HTML、SVG 和 Audit 展示。

OHLC 为空的时间戳不伪造价格、不填 0，继续按缺价处理并披露。

### 4.3 取消自动隔离

正式构建路径不再调用会从 `movement_review` 删除极端跳变重叠窗口的隔离逻辑。原来的“行情源连续性异常（不作市场异动）”正文区块取消，改为不影响主内容的人工复核提示。

价格异动阈值、强窗口/补充窗口规则和组并逻辑保持不变。

## 5. 完整度与报告状态

### 5.1 状态规则

不新增 `INVALID`。极端波动本身不触发降级。

继续使用现有状态：

- `FORMAL`：金十和 Yahoo 预检/新鲜度成功，新闻窗口覆盖通过，价格保护区间首尾覆盖通过，最晚分析新闻后 60 分钟观察期覆盖通过；
- `PARTIAL`：主数据仍有可展示内容，但上述覆盖条件至少一项未通过；
- `FAILED`：新闻和价格均失败且没有足够本地数据形成可用报告。

逐事件缺价、空 OHLC、重复/乱序检查和内部时间缺口必须披露。它们不得导致已抓到的价格、新闻或异动被隐藏；是否影响整体状态仍由现有覆盖硬门槛决定。

### 5.2 固定完整度字段

Markdown、HTML 首页和 Audit 至少展示：

- 新闻统计窗口；
- 最早/最晚原始新闻时间；
- 三段新闻覆盖数量；
- Brent 价格保护区间要求；
- 最早/最晚有效 K 线时间；
- 有效 K 线数量；
- 窗口首尾是否覆盖；
- 最晚分析新闻后 60 分钟是否覆盖；
- 逐事件价格不完整数量及 5/15/30/60 分钟缺失计数；
- 已发现的重复时间戳数量；
- 时间戳是否升序；
- 超过正常 5 分钟步长的时间缺口数量和最大缺口；
- 是否使用部分缓存及 `PARTIAL` 原因。

首页使用紧凑的“数据覆盖范围”说明，不移动 K 线图、蓝色详情面板或现有首页主体顺序。

## 6. 新闻与异动展示

### 6.1 `PARTIAL` 不删除新闻

覆盖不足时可以把因果置信度降为低或“暂无法确认”，但不得：

- 清空 `selected_news`；
- 清空 `homepage_news`；
- 清空 `selected_raw_ids`；
- 把已有异动组全部改写为无新闻组；
- 删除图表上的新闻标记；
- 删除蓝色面板中的合格新闻。

原有金十新闻硬门槛、直接能源传导、新增事实、发布时间、有效链接、去重和事件合并逻辑保持不变。

### 6.2 每个异动窗口

每个符合既有价格阈值的异动窗口均保留。窗口附近所有同时满足下列条件的新闻进入该窗口的展示集合：

- 与原油供应、出口、港口、油轮、霍尔木兹、制裁、OPEC+、产量、库存、地区冲突或运输安全直接相关；
- 有明确发布时间；
- 有有效金十 HTTP/HTTPS 原文链接；
- 提供新增事实；
- 不是重复行情描述、机构预测或其他既有噪音。

如果没有合格新闻，固定写：

> 暂未找到符合条件的金十新闻，原因暂无法确认，需人工继续核查。

极端价格波动、归因不确定或 `PARTIAL` 状态都不得减少符合条件的新闻。

## 7. ISW Iran Update

Markdown 和 HTML 始终保留独立标题 `ISW Iran Update`。

### 7.1 抓取成功

模块包含：

- Key Takeaways：中文 1 至 2 句话；
- 重要事实：要点列表；
- 对原油供应、霍尔木兹、军事行动、港口和航运的潜在影响；
- ISW 官方原文链接；
- 发布时间和抓取通道。

ISW 只服务于背景理解和“今日关注什么”，不反向改写本窗口价格归因。

### 7.2 抓取失败

模块仍保留标题和 ISW 列表链接，并固定写：

> ISW Iran Update：本次抓取失败，待下次运行补充。

失败不得删除模块，不得只留下没有标题的一句技术错误，也不得改变金十 + Brent 主链路状态。

## 8. 今日关注什么

现有“接下来关注什么”统一改为固定模块“今日关注什么”，Markdown 和 HTML 始终展示。

每日固定覆盖：

1. 霍尔木兹海峡是否继续通行；
2. 油轮、港口和 AIS 船位变化；
3. 制裁、豁免和出口政策；
4. OPEC+ 及主要产油国政策；
5. 地区冲突是否升级或缓和；
6. EIA/API 库存或其他重要供需数据；
7. 当天 ISW Iran Update 中最值得跟踪的事项。

ISW 抓取成功时，第 7 项优先使用最新 Update 的中文要点。ISW 抓取失败时，模块仍输出前六项和已获取的金十直接能源新闻，并明确写：

> 指定网站本次抓取失败，以下内容根据已获取的相关新闻和ISW信息整理。

失败状态下不编造 ISW 结论；只有成功缓存中的既有 ISW 内容可以作为 ISW 信息复用。

## 9. 首页固定展示

首页保持现有整体布局和交互，固定展示：

1. Brent 当前价格；
2. 当日涨跌幅；
3. 最高价和最低价；
4. 所有符合阈值的价格异动窗口；
5. 每个窗口对应的全部合格金十新闻；
6. ISW Iran Update；
7. 今日关注什么；
8. 数据覆盖范围；
9. 部分缓存说明；
10. `PARTIAL` 原因。

K 线图继续位于蓝色详情框上方，蓝色面板默认显示全日重要新闻，其他首页结构和交互保持不变。
