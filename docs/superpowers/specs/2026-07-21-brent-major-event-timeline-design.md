# Brent 首页重大事件时间轴与 ISW 提炼设计

## 目标

在不改变现有“先看价格、再找原因”的 Brent 异动重点复盘逻辑下，让正式日报 HTML 同时展示全部合格重大事件，便于按发布时间核对价格大幅波动附近的风险信息；同时将 ISW Iran Update 的 Key Takeaways 提炼为简洁中文要点。右侧“接下来关注什么”、正式 Markdown 与 Audit 的内容和生成逻辑保持不变。

## 合格重大事件口径

首页时间轴收录统计窗口内同时满足以下条件的原始新闻：

- 命中重大主题规则；
- 通过直接能源供应或运输硬门槛；
- 不是重复报道；
- 不是汇总转述。

时间轴按北京时间发布时间升序展示，并包含已经进入价格异动重点复盘的新闻。后者标记“已进入重点复盘”，但不改变其原有 K 线蓝点和归因说明。

## 页面与交互

正式 HTML 保持标题、市场主线、指标、K 线图和蓝色详情框的现有顺序。K 线图及其蓝色时间点仍只表示通过价格异动归因门槛的新闻。

在蓝色详情框下方增加“重大事件时间轴”：

- 每条默认仅显示北京时间、短标题和事件主题标签；
- 使用紧凑的纵向时间轴，而非把全部标签叠加到 K 线上，避免高新闻量窗口遮挡 K 线或使既有归因点失去可读性；
- 点击任一条后，在现有蓝色详情框显示“重大事件追踪（非价格归因）”、完整标题、主题、北京时间、有效原文链接和一到两句简短说明；
- 若该事件已进入重点复盘，详情中明确保留“已进入重点复盘”状态；
- 点击重大事件不会渲染价格反应卡，也不会把事件写为该段价格异动原因；
- 无合格事件时显示明确空状态，不使用缓存事件填充。

正式 HTML 可从报告生成时已经得到的窗口审计数据接收独立的重大事件展示数据；不在 HTML 阶段重新抓取、重新分类或改写 Markdown。`build_html_report` 保持向后兼容，缺少该数据时仅不渲染时间轴。

## ISW Iran Update

正式 HTML 的“伊朗局势更新”卡片从已抓取并缓存的 ISW 原文中提取 Key Takeaways。展示层按以下规则处理：

- 生成 3 至 5 条中文要点，每条一至两句；
- 优先保留伊朗局势、霍尔木兹与能源运输、制裁、油气供应风险和地区军事升级/降温信息；
- Key Takeaways 之外若正文存在满足相同优先级的新增重要事实，最多追加两条；
- 每条摘要保留 ISW 官网原文链接，且清晰标识其只用于下一时段风险监测，不能反向解释本窗口 Brent 异动；
- ISW 获取、缓存或翻译失败时，保留现有失败说明与官网列表入口，不生成未经来源支持的中文结论。

不修改正式 Markdown 中的外部 update 段落，也不改变 Audit 中的 ISW 审计记录。

## 数据流与边界

1. 日报生成阶段从已建好的窗口审计中筛出合格重大事件，并按发布时间构建只读时间轴项目。
2. 价格异动复盘仍使用既有 `selected_raw_ids` 和 K 线蓝点数据，不因时间轴项目而改变。
3. 正式 HTML 接收价格异动事件、重大事件时间轴项目和 ISW 展示要点，分别渲染并在同一个详情框中根据点击来源显示对应内容。
4. Audit 仍列出全部重大候选、未入选原因和未充分定价风险；正式 Markdown 保持当前内容不变。

## 降级与可访问性

- 时间轴项目使用稳定原始新闻 ID；缺少有效 HTTP(S) 原文链接时保留该事件并明确显示链接不可用，不伪造跳转地址。
- 时间轴按钮和 K 线交互点均支持鼠标、Enter 和 Space；当前选中项有可见状态。
- 小屏幕下时间轴保持单列，短标题自动换行，不压缩或遮挡主题标签。

## 验证

- 先写失败测试，验证合格重大事件的硬门槛、去重和非汇总筛选，及按发布时间排序。
- 验证正式 HTML 同时保留 K 线重点复盘交互和新增时间轴；点击时间轴只显示非归因详情，不显示价格归因卡。
- 验证核心复盘新闻在时间轴中标记“已进入重点复盘”。
- 验证 ISW 卡片显示中文提炼要点、原文链接、最多两条正文补充，以及失败回退。
- 验证右侧“接下来关注什么”渲染内容与当前固定四条完全一致。
- 运行全量单元测试，并重新生成当天 HTML 后检查时间轴、ISW 摘要、K 线与蓝色详情框顺序和移动端样式。
