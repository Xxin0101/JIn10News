# Brent 项目接管审计与实施计划

审计基线为公开仓库 `main` 的 `e4fbc2d`。对照了根目录 README、两份 Handoff、两份 Spec，以及 `docs/daily-reports/2026-08-05/` 的日期专属 Handoff 和 Spec。历史声明只代表原工作环境，对当前版本的判断以代码、Cloud 测试和抓取结果为准。

## 数据与代码

| 环节 | 现有实现 | 运行条件 |
| --- | --- | --- |
| 主新闻 | 金十公开快讯分页，按发布时间截取北京时间前一日 08:00 至当日 08:00 的半开区间。保留原始 ID、原文链接、时间和原始载荷 | `fetcher.py`。需要金十公网接口可达，历史深度受公开接口限制 |
| 行情 | Yahoo Finance `BZ=F` 5 分钟 OHLC，入库采用 UTC，回补扩展前 30 分钟与后 65 分钟 | `brent.py`、`storage.py`。需要 Yahoo；SQLite 可直接在 Cloud 运行 |
| 规则与归因 | 新闻筛选、去重、事件分组与前后价格匹配；30 分钟异动先于候选新闻归因。首选阈值 0.50%，无强异动时补充 0.25%。识别缺口、未定价风险和解释不足 | `processor.py`、`eventing.py`、`reaction.py`、`tracker.py`。有缓存即可本地计算 |
| 滚动日报 | 输出 Markdown、HTML、SVG、两份 Audit。ISW Iran Update、翻译及金十特朗普专题作为单独背景 | `tracking_report.py`、`tracking_chart.py`、`external_update.py`、`trump_update.py`。外部模块需要网络或日期化缓存 |
| 日度 Price Layer | 按截至最新完整会话的六模型历史 OOS 结果排名，运行选中模型。使用价格历史、对账收盘并按 ICE 日历确定目标 | `price_layer.py`。依赖外部项目与其虚拟环境，含模型数据和 OOS CSV。通过 `BRENT_PRICE_LAYER_ROOT` 配置，缺数据或依赖时显式降级 |
| 专项方向预测 | Model A 为价格特征（LightGBM 或通用路径的 Logistic）；Model B 为结构化新闻，Model C 组合价格与新闻，样本不足时限制概率发布。周一入口读已冻结的周五快照。同日预测另有入口 | `forecast.py`、`forecast_pipeline.py`。真实预测需要相应冻结快照、本地历史及模式对应依赖 |
| 旧 Word 日报 | 独立新闻文档和结构化日志 | `run_jin10_report.py`、`report.py`，需要 `python-docx` |

基线 `python -m unittest discover -s tests` 通过 171 项。Cloud 可执行标准库跟踪器、SQLite、规则、HTML/SVG 和离线测试。仓库 CI 配置 Python 3.10 与 3.12。生产无人值守仍需可持续运行的调度器和持久化数据库、缓存、产物目录。现有 `auto` 是进程内 5 分钟循环。

## 交接差异与运行缺口

- 2026-08-05、09-04、09-10 的正式产物和运行日志，以及 08-24 周一预测的冻结快照，均未随公开仓库提供。文档记录了历史结果和部分哈希，本次无法独立复算或核对这些文件。旧 Handoff 中关于未提交改动与唯一历史修复的描述只适用于原工作树，当前公开基线已包含结果清单版本与复用逻辑。
- `report` 复用 SQLite 主数据，仍可请求 ISW、翻译和特朗普专题，并可能调用外部 Price Layer。它还会重算并写入反应与分组。需要硬只读的周末报告使用 `forecast-report`。
- README 中“从当前公开快讯流逐页回溯”的表述落后于 `fetch_flashes_between`。历史分页从指定窗口截止时刻开始。
- 常规 Price Layer 的标题沿用“今日”，目标实际由最近完整交易会话推算。原 HTML 与 Markdown 模型披露也有差异，HTML 缺少 MAE、RMSE、OOS 样本数及截止日。
- 地缘、供应和 OPEC 规则已存在。常规日报尚缺少覆盖库存和需求的独立证据列表及显式情景置信度。没有独立 EIA、IEA 或 OPEC 数值时间序列管道，专题快讯也不等同于官方指标表。
- 待处理运行风险。历史回补允许单一路抓取失败后继续，CLI 退出码为 0 只说明命令走完，生产调度应读取最终报告/Audit 状态。需关注原站限流、金十分页缺口、Yahoo 连续代码换月、5 分钟缺口以及 ICE 假日覆盖。真实报告还需验收回测与实时数据口径相容性。
- 本次复现了周六滚动窗口的行情截止误判。旧逻辑要求 K 线逼近北京时间 08:00，正常周五收盘被归为缺口。首版对 Yahoo BZ=F 的周六窗口识别 NYMEX BZ 常规收盘最后一根 5 分钟 K 线，缺最后一根时仍不豁免。常规 Price Layer 的收盘输入同步处理纽约夏令时，专项冻结路径继续使用其历史口径。BZ 的节假日提前收盘仍需独立交易日历。参见 [NYMEX 合约规则](https://www.cmegroup.com/rulebook/NYMEX/6/698.pdf) 和 [CME 交易时段](https://www.cmegroup.com/trading-hours.html)。

## 首版 Cloud 验证

- `2026-11-21 08:00` 截止窗口实测，金十公开分页 71 页、1,404 条原始快讯，Yahoo 窗口内 255 根 K 线。独立的通用行情探测曾收到 429，指定时段的既有回补调用成功。日内区间变化按第一根开盘至最后一根收盘计算。
- 新闻覆盖至北京时间 06:17:29，最后一根 5 分钟 K 线始于 05:55。两个有效时段行情缺口分别为 15、25 分钟，审计保留 9 条逐事件价格缺失。
- 同一主数据快照重算得到 `FORMAL`。ISW 官网与特朗普专题均成功，但只进入独立背景。六模型 OOS CSV 在 Cloud 缺失，真实报告没有发布本期价格预测。下一交易日研究判断是观望，置信度低。
- `sample-report` 使用合成输入与内存 SQLite，可断网重复运行。CI 只保存合成样本五件套。真实运行数据库、日志和日报留在本地忽略目录。

## 优先级与实施步骤

1. P0 报告证据。在既有常规滚动报告中展示行情时间与来源、分类快讯、规则方向和传导。保持现有异动归因和专项预测的输入边界。测试边界时刻、原文链接和 HTML。
2. P0 研究展望。复用 Price Layer，补齐模型来源与样本外披露。用独立的研究判断给出下一交易日和条件风险，数据或模型缺失时明确观望。验证降级和周末目标日。
3. P0 可重复验收。先尝试公开的主数据源。无法取得可核验窗口时，用内存 SQLite 运行显式标记的样本，验证既有生成器、五件套和 CI。分支提交代码和文档。
4. P1 实盘运行。配置稳定数据通道、持久化目录、六模型项目和 ICE 假日更新。以覆盖审计验证一个完整真实会话。
5. P2 无人值守。接入外部调度，按最终状态做失败告警和产物留存。先验证真实数据稳定性，再确定任务周期与重试策略。
