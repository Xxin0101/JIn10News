# Brent 蓝色详情框全量新闻设计

## 目标

正式 HTML 首页的蓝色详情框成为交易员阅读当日重要金十新闻的完整入口。保留价格先行和现有 Brent 异动阈值，但不再因核心归因优先级隐藏其他合格新闻，也不再将合格重大事件单独留在首页时间轴或 Audit 中。

## 不变项

- Brent 异动扫描、0.50% 强窗口优先及无强窗口时 0.25% 补充窗口的规则不变。
- 每个异动组的新闻匹配窗口仍为组开始前 45 分钟至组结束后 15 分钟。
- `selected_news`、核心驱动、次要驱动和市场解读仍按现有严格归因规则生成；它们不等同于首页展示集合。
- 正式 Markdown 保持现有价格归因正文口径；独立 Audit 继续记录筛选、去重、排除和首页去向。
- ISW 卡片和右侧“接下来关注什么”不在本次范围内。

## 首页展示资格

异动组内每条原始金十新闻独立判断。满足下列全部条件即进入该组蓝色详情内容：

1. 具备直接原油供给、能源运输、港口、油轮、制裁、OPEC、产量、库存、关键航道或地缘冲突的传导路径。
2. 新鲜度为“新增事实”。
3. 具有有效的 `http`/`https` 金十原文链接。
4. 未被现有去重链路标记为重复；重复快讯只保留主条目及其合并关系。
5. 不属于股市/汇率/纯宏观/机构预测/油价自身涨跌或其他既有正式报告噪音。

归因优先级、方向一致性、置信度和是否成为核心驱动均不参与展示资格判断。它们仅用于同一时间戳的次级排序与价格状态说明。

## 蓝色详情框交互

### 默认全日视图

蓝色详情框初始显示“全日重要新闻”，按价格异动组开始时间排列；组内再按新闻发布时间排列，同一时间戳才使用既有优先级作为次级顺序。

每条新闻显示：发布时间、完整标题、简短影响说明、价格状态和金十原文链接。

- 核心/次要驱动保留现有“主要驱动”或“次要驱动”价格状态。
- 其他合格的组内新闻显示“同期相关信息”或“价格先于新闻，不作该段归因”，不能被写成单一价格原因。

### K 线聚焦

点击已匹配新闻标记或未解释异动带后，蓝色详情框仅显示相应异动组的全部合格新闻及原有价格反应、市场解读。框内提供“查看全日重要新闻”入口，恢复默认全日视图。

### 未匹配异动的重大事件

重大事件强制候选池中的新闻如满足展示资格、但未落入任何显著异动组的匹配窗口，则放在同一蓝色详情框的末尾小节：

`⚠ 重大事件`

每条均注明：`暂未发现可直接匹配的Brent显著异动，需持续关注后续影响。`

正式 HTML 删除独立“重大事件时间轴”区块，不引入新的首页卡片或标签页。

## 数据边界与审计

- 建立仅供 HTML 使用的展示视图模型，包含每个价格异动组的完整合格新闻和未匹配异动的重大事件；不修改数据库 schema，也不把展示状态写回核心归因字段。
- 一条新闻若落在多个异动组的既有匹配窗口内，按每个组的窗口规则展示，以保证每个异动组都不遗漏其窗口内的合格新闻。
- Audit 为每条重大候选记录首页去向：所展示的异动组、未匹配重大事件小节、重复合并对象或合法排除原因。
- “被更高优先级事件替代”和“未达到核心驱动置信度”不得再作为合格新闻未进首页的原因。
- 首页未展示仅允许：重复已合并、非新增事实、链接无效、无直接油市传导路径或明确噪音。

## 实现边界

- 在 `tracking_report.py` 内新增展示资格和展示项构建逻辑，扩展 `FormalReportPresentation`，并让 HTML 渲染/脚本消费该展示模型。
- 现有 Markdown 到 HTML 的价格指标与图表解析保持不变；展示模型只覆盖蓝色详情框新闻列表和默认全日视图。
- 删除首页重大事件时间轴 HTML/CSS/脚本，不删除 Audit 中的强制候选池审计。

## 验证

1. 为异动组内多条合格新闻、重复合并、价格先于新闻标注和全日/聚焦切换新增单元测试。
2. 为未匹配异动的合格重大事件新增测试，确认其只出现在同一蓝色详情框的 `⚠ 重大事件`小节，而不是独立首页区块。
3. 为 Audit 新的首页去向状态新增测试，确认不存在“被更高优先级事件替代”导致的首页遗漏。
4. 回测 `2026-07-20 20:10｜胡塞武装宣布对沙特实施海上禁令`，确认其在对应 2026-07-21 08:00 报告异动组的蓝色详情内容中出现，并保留有效金十链接。
5. 运行完整单元测试，并用 `report --date 2026-07-21` 重生成正式 HTML、Markdown 和 Audit，检查默认蓝框、K 线聚焦、返回入口、无独立重大事件时间轴及 Audit 路由。
